Версия проекта - 1.0.0.0

**Запрос:**
- Изменить метод авторизации по номеру телефона на простую регистрацию (email/пароль) из-за ошибки auth/operation-not-allowed.
- Создать админ-аккаунт с возможностью смены пароля.
- Простая регистрация для потребителей без подтверждения.
- Регистрация поставщиков только после подтверждения админа.
- Создать панель для админа для подтверждения регистрации поставщиков.
- Реализовать структуру номенклатуры (Категория -> Вид -> Группа -> Наименование).
- Обновить статусы заявок (Открыт, Назначен на продавца, В обработке, Выполнен, Отказан).

**Анализ:**
Текущая реализация использует Firebase Phone Auth, которая вызывает ошибку из-за ограничений домена или настроек проекта. Переход на Email/Password аутентификацию решит эту проблему и упростит процесс тестирования MVP. 
Также необходимо добавить роль администратора, который сможет управлять статусами верификации поставщиков (`verificationStatus`), и создать соответствующий интерфейс (Admin Dashboard).
Структура базы данных должна быть расширена для поддержки каталога товаров/услуг (Номенклатуры) и новых статусов заявок.

**Формализованное требование после Анализа:**
1. Заменить Phone Auth на Email/Password Auth в `AuthModal.tsx`.
2. Обновить `OnboardingModal.tsx` для сохранения email.
3. Создать страницу `/admin` для управления пользователями (подтверждение/отклонение поставщиков).
4. Обновить `firebase-blueprint.json` и `firestore.rules` для поддержки каталога (`Product`) и новых статусов заявок.
5. Обеспечить безопасность: только пользователи с `role == 'admin'` могут менять `verificationStatus`.

**Требуется изменить/разработать:**
- `components/AuthModal.tsx` (переписать на Email/Password)
- `components/AuthProvider.tsx` (обновить логику входа/выхода)
- `app/admin/page.tsx` (создать новую страницу)
- `firebase-blueprint.json` (добавить Product, обновить Request)
- `firestore.rules` (обновить правила доступа)
