## 1. Введение

### 1.1 Цель документа

Данный документ описывает **поведение системы** Stroy.kg: как каждый модуль реагирует на конкретные входные данные пользователя, какие условия проверяются, какие результаты возвращаются и какие экранные переходы происходят.

### 1.2 Аудитория

- Разработчики (frontend/backend)
- QA-инженеры (для создания тест-кейсов)
- UI/UX дизайнеры (для понимания поведенческих сценариев)

### 1.3 Обозначения

- **[BUYER]** — поведение для роли Заказчик (consumer)
- **[SUPPLIER]** — поведение для роли Поставщик (supplier)
- **[DEVELOPER]** — поведение для роли Застройщик (developer)
- **[ADMIN]** — поведение для роли Администратор (admin)
- **[ALL]** — поведение для всех ролей
- **[V2+]** — требуется верификация уровня 2 и выше
- **→** — переход к следующему состоянию/экрану

## 2. Поведение системы аутентификации

### 2.1 Модальное окно входа (AuthModal)

#### Вход по email и паролю (основной метод)

| Вход | Условие | Поведение системы | Выход |
|------|---------|-------------------|-------|
| Нажатие "Войти" в шапке | Пользователь не аутентифицирован | Открывается модальное окно с формой email+пароль | Модальное окно видимо |
| Ввод email | Валидный формат | Поле email заполнено | — |
| Ввод пароля | Непустое поле | Кнопка "Войти" активна | Состояние enabled |
| Чекбокс "Я новый пользователь" | Отмечен | Отображается выбор роли (Покупатель / Поставщик) | Выбор роли видим |
| Нажатие "Войти" (Supabase) | Email + пароль заполнены | `signInWithPassword({ email, password })`. При ошибке `Invalid login credentials` → `signUp({ email, password, options: { data: { role } } })` | Сессия создана |
| Нажатие "Войти" (Mock) | Email существует в БД, пароль верный | Вход через `getMockUserByEmail`. Данные в localStorage. | Главная страница |
| Нажатие "Войти" (Mock) | Email не найден в БД | Ошибка "Пользователь не найден" | Ошибка |
| Нажатие "Войти" (Mock) | Пароль неверный | Ошибка "Неверный пароль" | Ошибка |
| Успешный вход | Нет onboarding | `onAuthStateChange` загружает профиль → OnboardingModal | Onboarding |
| Успешный вход | Onboarding пройден | Закрытие модалки. Данные в AuthContext. | Главная страница |

#### Вход по телефону (stub/mock)

| Вход | Условие | Поведение | Выход |
|------|---------|-----------|-------|
| Переключение на вкладку "Телефон" | — | Отображается поле ввода телефона | UI переключён |
| Нажатие "Войти" (Supabase) | Любой номер | Ошибка "Вход по телефону временно недоступен. Используйте почту и пароль." | Ошибка |
| Нажатие "Войти" (Mock) | Номер существует | Вход через `getMockUser(phone)`, проверка пароля | Главная страница |
| Нажатие "Войти" (Mock) | Номер не существует, "Я новый пользователь" | Создание через `createMockUser(phone, role)` | Главная страница |

#### Вход администратора

| Вход | Условие | Поведение | Выход |
|------|---------|-----------|-------|
| Ввод admin@stroy.kg + пароль | Пароль верный (admin123/admin) | Стандартный вход через email+пароль | Главная (admin view) |
| Ввод admin@stroy.kg + пароль | Пароль неверный | Сообщение "Неверный пароль" | Ошибка |

### 2.2 Управление сессией (AuthProvider)

| Событие | Условие | Поведение |
|---------|---------|-----------|
| Загрузка приложения | localStorage содержит mockUser | Восстановление данных пользователя из localStorage. `isLoading = false`. | 
| Загрузка приложения | localStorage пуст | `user = null`, `isLoading = false` |
| Выход (logout) | Пользователь нажал "Выйти" | Очистка user, localStorage, admin view-as. Перенаправление на `/`. |
| Обновление профиля | Вызов updateProfile(data) | Обновление данных в mockDb + localStorage + контексте |

### 2.3 Гейты доступа

| Функция | Условие | Результат |
|---------|---------|-----------|
| `canAccessChat` | `verificationLevel >= 2` | `true` — доступ к чатам разрешён |
| `canAccessChat` | `verificationLevel < 2` | `false` — отображается блок "Требуется верификация Level 2" |
| `canAccessRequests` | `verificationLevel >= 2` | `true` — создание заявок разрешено |
| `canAccessRequests` | `verificationLevel < 2` | `false` — отображается блок с требованием верификации |

## 3. Поведение главной страницы (Лента)

### 3.1 Определение режима отображения

| Условие | Режим | Описание |
|---------|-------|----------|
| `role === 'consumer'` | Покупательская лента | Товары, рекомендации, навигация покупателя |
| `role === 'supplier'` | Поставщическая лента | Входящие заявки, боковая панель |
| `role === 'developer'` | Поставщическая лента | Аналогично supplier |
| `role === 'admin'` | Зависит от view-as | При view-as — соответствующая роль; без view-as — supplier |
| `user === null` | Гостевая лента | Товары без персонализации, CTA "Войти" |

### 3.2 Секция приветствия

| Условие | Поведение |
|---------|-----------|
| Пользователь аутентифицирован, есть companyName | Показывает "Добро пожаловать, [companyName]!" |
| Пользователь аутентифицирован, нет companyName | Показывает "Добро пожаловать, [name]!" |
| verificationLevel < 2 | Баннер: "Пройдите верификацию для доступа ко всем функциям" + ссылка на профиль |
| verificationLevel >= 2 | Баннер верификации скрыт |

### 3.3 Навигационные кнопки

**[BUYER]:**

| Кнопка | Действие |
|--------|----------|
| "Каталог" | Переход на `/catalog` |
| "Создать заявку" | Переход на `/create` |
| "Поставщики" | Переход на `/catalog` с режимом supplier view |
| "Чаты" | Переход на `/chats` |

**[SUPPLIER]:**

| Кнопка | Действие |
|--------|----------|
| "Мой каталог" | Переход на `/catalog` с флагом supplier-own |
| "Добавить товар" | Переход на `/add-product` |

### 3.4 Секция рекомендаций [BUYER]

| Условие | Поведение |
|---------|-----------|
| Есть товары с `isPromoted = true` ИЛИ `isTop = true` | Отображаются первые 4 товара в горизонтальном скролле |
| Нет таких товаров | Секция "Рекомендации" скрыта |

### 3.5 Баннер "Создать заявку" [BUYER]

| Условие | Кнопка | Переход |
|---------|--------|---------|
| `canAccessRequests === true` | "Создать заявку" | `/create` |
| `canAccessRequests === false` | "Верификация →" | `/profile` |

### 3.6 Фильтр ленты

| Фильтр | Поведение |
|--------|-----------|
| "Все" (по умолчанию) | Отображаются все товары/заявки |
| "Товары" | `nomenclatureCategory === 'Товар'` |
| "Услуги" | `nomenclatureCategory === 'Услуга'` |

### 3.7 Список товаров [BUYER]

| Вход | Условие | Поведение |
|------|---------|-----------|
| Загрузка страницы | Есть опубликованные товары | Отображаются карточки товаров (3 в ряд) |
| Загрузка страницы | Нет товаров | Сообщение "Товары не найдены" |
| Нажатие "Запросить" на карточке | canAccessRequests = true | Переход на `/create?productId=[id]` |
| Нажатие "Запросить" на карточке | canAccessRequests = false | Переход на `/profile` |
| Нажатие иконки чата на карточке | canAccessChat = true | Переход на `/chats` |
| Нажатие имени поставщика | — | Переход на `/supplier/[id]` |

### 3.8 Список заявок [SUPPLIER]

| Вход | Условие | Поведение |
|------|---------|-----------|
| Загрузка страницы | Есть заявки со статусом OPEN/ASSIGNED/IN_PROGRESS | Отображаются карточки заявок |
| Загрузка страницы | Нет заявок | Сообщение "Нет подходящих заявок" |
| Нажатие на заголовок заявки | — | Переход на `/request/[id]` |
| Нажатие "Подробнее" | — | Переход на `/request/[id]` |

## 4. Поведение каталога

### 4.1 Режимы каталога

| Вход | Результат |
|------|-----------|
| URL `/catalog` (покупатель) | Режим "Товары" по умолчанию, сетка |
| URL `/catalog` (поставщик, без флага) | Режим общего каталога |
| URL `/catalog` + supplier-own flag | Режим "Мой каталог" — только товары текущего поставщика |
| Нажатие "Товары" | Режим отображения продуктов |
| Нажатие "Поставщики" | Режим отображения поставщиков |

### 4.2 Переключение вида (Grid / Table)

| Вход | Поведение |
|------|-----------|
| Нажатие иконки сетки | Отображение карточек товаров (3 колонки) |
| Нажатие иконки таблицы | Отображение табличного представления |
| Нажатие "Настройки" в таблице | Выпадающий список выбора колонок |
| Тоггл колонки в настройках | Колонка показывается/скрывается |

### 4.3 Поисковая строка

| Вход | Поведение |
|------|-----------|
| Ввод текста в поле поиска | Фильтрация в реальном времени по: `name`, `supplierName`, `description`, `tags[]` |
| Пустое поле | Все товары отображаются (с учётом других фильтров) |

### 4.4 Фильтрация по категории

| Вход | Поведение |
|------|-----------|
| Нажатие "Купить товар" | `category = 'Товар'`. Сброс: вид, группа. Обновление списка видов. |
| Нажатие "Купить услугу" | `category = 'Услуга'`. Сброс: вид, группа. Обновление списка видов. |
| Повторное нажатие (снятие) | `category = null`. Сброс всех зависимых фильтров. |

### 4.5 Каскадная фильтрация

| Шаг | Вход | Поведение | Зависимости |
|-----|------|-----------|-------------|
| 1 | Выбор категории | Обновляется список видов | Сброс: вид, группа |
| 2 | Выбор вида | Обновляется список групп | Сброс: группа |
| 3 | Выбор группы | Обновляется фильтр | Нет зависимостей |
| 4 | Выбор этапа строительства | Независимый фильтр | Нет |

### 4.6 Расширенные фильтры

| Фильтр | Вход | Поведение |
|--------|------|-----------|
| Цена min | Число | Фильтрация `price >= min` |
| Цена max | Число | Фильтрация `price <= max` |
| Рейтинг 4+ | Нажатие | Фильтрация `rating >= 4.0` |
| Рейтинг 4.5+ | Нажатие | Фильтрация `rating >= 4.5` |
| Рейтинг 4.8+ | Нажатие | Фильтрация `rating >= 4.8` |
| Только продвигаемые | Тоггл | Фильтрация `isPromoted === true` |
| Только новые | Тоггл | Фильтрация `isNew === true` |

### 4.7 Индикатор активных фильтров

| Условие | Поведение |
|---------|-----------|
| Кол-во активных фильтров > 0 | Бейдж с числом рядом с кнопкой фильтров. Кнопка "Сбросить все" видима. |
| Нажатие "Сбросить все" | Все фильтры сбрасываются: категория, вид, группа, этап, цена, рейтинг, тогглы |
| Кол-во активных фильтров = 0 | Бейдж и кнопка "Сбросить" скрыты |

### 4.8 Режим поставщиков

| Вход | Поведение |
|------|-----------|
| Переключение на поставщиков | Загружается список поставщиков (роль supplier). Применяется фильтр по типу. |
| Фильтр "Все" | Все поставщики |
| Фильтр "Только товары" | Поставщики, у которых есть продукты с категорией "Товар" |
| Фильтр "Только услуги" | Поставщики, у которых есть продукты с категорией "Услуга" |
| Фильтр "Смешанные" | Поставщики с обоими типами продуктов |
| Нажатие "Открыть каталог поставщика →" | Переход на `/supplier/[id]` |

### 4.9 Действия на карточке товара

| Действие | Условие | Поведение |
|----------|---------|-----------|
| Нажатие "Запросить" | V2+, buyer | Переход на `/create?productId=[id]` |
| Нажатие "Запросить" | V < 2 | Переход на `/profile` |
| Нажатие иконки чата | V2+, canAccessChat | Переход на `/chats` |
| Нажатие имени поставщика | Любой | Переход на `/supplier/[supplierId]` |

## 5. Поведение модуля заявок

### 5.1 Гейты доступа на странице `/create`

| Состояние | Поведение экрана |
|-----------|-----------------|
| `user === null` | Сообщение "Войдите в систему для работы с заявками" + кнопка "Войти" → открытие AuthModal |
| `user !== null`, `verificationLevel < 2` | Сообщение "Для работы с заявками необходима верификация уровня 2. Заполните данные ИНН/паспорта." + кнопка → `/profile` |
| `role === 'consumer'`, V2+ | Отображается интерфейс покупателя (форма + список) |
| `role === 'supplier' \| 'developer'`, V2+ | Отображается интерфейс поставщика (входящие заявки) |
| `role === 'admin'` | Зависит от view-as mode |

### 5.2 Форма создания заявки [BUYER]

#### Табы

| Вход | Поведение |
|------|-----------|
| Нажатие "Создать заявку" | Отображается форма создания |
| Нажатие "Мои заявки (N)" | Отображается список заявок пользователя. N = количество. |

#### Заполнение формы

| Поле | Вход | Валидация | Поведение при ошибке |
|------|------|-----------|---------------------|
| Категория | Кнопка Товар/Услуга | Обязательно | Подсветка |
| Название | Текст | Обязательно, min 3 символа | Подсветка поля |
| Количество | Число | ≥ 0 | — |
| Единица | Dropdown (шт, м², м³, т, кг, п.м, л, комплект) | Обязательно | — |
| Срок | Дата | Не в прошлом | — |
| Бюджет | Число (KGS) | ≥ 0 | — |
| Описание | Текст | Рекомендуется | — |
| Фото/документы | Drag & drop зона | — | — |

#### Секция уточнений (Clarifications)

| Вход | Поведение |
|------|-----------|
| Нажатие "Уточнения ▼" | Секция разворачивается. Синий информационный блок: "Уточнения помогут поставщикам лучше понять ваш запрос". |
| Выбор вида | Динамические кнопки на основе выбранной категории. При выборе — обновляется список групп. |
| Выбор группы | Динамические кнопки на основе вида. При выборе — отображаются поля характеристик. |
| Заполнение характеристик | Текстовые поля, зависящие от группы. Пример (Бетон): Марка, Класс прочности, Морозостойкость, Подвижность, Объём. |

#### Pre-fill с карточки товара

| Вход | Поведение |
|------|-----------|
| URL содержит `?productId=X` | Загрузка данных товара X. Автозаполнение: категория, вид, группа, характеристики, название (из товара). |
| productId не найден | Форма отображается пустой |

#### Отправка формы

| Вход | Поведение |
|------|-----------|
| Нажатие "Опубликовать заявку" | Валидация полей. Если ОК — создание заявки (createMockRequest). Уведомление поставщикам. Переключение на tab "Мои заявки". |
| Нажатие при невалидной форме | Подсветка невалидных полей |

### 5.3 Список заявок покупателя

| Элемент | Поведение |
|---------|-----------|
| Категория | Бейдж "Товар"/"Услуга" |
| Статус | Цветной бейдж (синий/оранжевый/primary/зелёный/красный) |
| Назначенный поставщик | Отображается имя поставщика (если назначен) |
| "Отменить заявку" | Видна если статус ≠ COMPLETED и ≠ REJECTED. Удаление заявки. |

### 5.4 Обработка заявок [SUPPLIER]

| Статус заявки | Отображаемые кнопки | Действие → Новый статус |
|---------------|--------------------|-----------------------|
| OPEN | "Взять в работу" | OPEN → ASSIGNED (supplierId/Name назначаются) |
| ASSIGNED | "Начать обработку" | ASSIGNED → IN_PROGRESS |
| IN_PROGRESS | "Завершить", "Отклонить" | → COMPLETED или → REJECTED |
| COMPLETED | — (нет кнопок) | Финальный статус |
| REJECTED | — (нет кнопок) | Финальный статус |

При каждой смене статуса:
1. Статус обновляется в БД (`updateRequestStatus`)
2. Создаётся уведомление для автора заявки с текстом: `"Заявка '[title]' — [statusLabel]"`

### 5.5 Боковая панель [BUYER]

| Секция | Содержание |
|--------|-----------|
| "Как работают заявки" | 4 шага: 1. Заполните форму → 2. Поставщики получат уведомление → 3. Поставщик берёт в работу → 4. Выполнение заказа |
| Легенда статусов | 5 статусов с цветными индикаторами и описаниями |
| Статистика | Активные заявки: N, Всего заявок: N |

## 6. Поведение модуля товаров

### 6.1 Гейт доступа `/add-product`

| Условие | Поведение |
|---------|-----------|
| `role === 'consumer'` | Сообщение "У вас нет доступа к добавлению товаров" |
| `role === 'supplier' \| 'developer' \| 'admin'` | Отображается форма добавления товара |

### 6.2 Пошаговый выбор номенклатуры

| Шаг | Вход | Поведение | Зависимости |
|-----|------|-----------|-------------|

## 8. Поведение профиля и верификации

### 8.1 Информационная карточка `/profile`

| Данные | Условие отображения | Формат |
|--------|---------------------|--------|
| Аватар | Всегда | Круг с первой буквой имени |
| Имя | Всегда | Заголовок |
| Уровень верификации | Всегда | Цветной бейдж (0-3) |
| Email | Если заполнен | Текст + ✓ (если подтверждён) |
| Компания | Если role = supplier/developer | Текст |
| ИНН | Если заполнен | Текст |
| Роль | Всегда | Бейдж (Consumer/Supplier/Developer/Admin) |
| Подписка | Если role = supplier/developer | Бейдж тарифа |

### 8.2 Прогресс верификации

| Уровень | Индикатор | Условие unlock |
|---------|-----------|----------------|
| 0 | Серый | Базовый (регистрация телефона) |
| 1 | Синий | `phoneVerified && emailVerified` |
| 2 | Оранжевый | Уровень 1 + ИНН/паспорт |
| 3 | Зелёный | Уровень 2 + лицензии/сертификаты |

### 8.3 Процесс верификации уровня 1

| Шаг | Вход | Поведение |
|-----|------|-----------|
| 1 | Нажатие "Подтвердить" на карточке Level 1 | Открытие модалки верификации email |
| 2 | Ввод email | Кнопка "Подтвердить" активна |
| 3 | Supabase-режим | **Stub**: email считается подтверждённым при входе через `signUp`. `emailVerified = true` автоматически. |
| 3a | Mock-режим | `emailVerified` устанавливается в `true`. Пересчёт уровня верификации. Закрытие модалки. |

### 8.4 Процесс верификации уровня 2

| Шаг | Вход | Поведение |
|-----|------|-----------|
| 1 | Нажатие "Подтвердить" на карточке Level 2 | Открытие модалки верификации ИНН |
| 2 | Ввод ИНН | Минимум 10 цифр |
| 3 | Отправка | `submitInnVerification(uid, inn)`. В mock: автоматическое одобрение. Пересчёт уровня. |
| 3a | ИНН < 10 цифр | Кнопка "Отправить" заблокирована |

### 8.5 Процесс верификации уровня 3

| Шаг | Вход | Поведение |
|-----|------|-----------|
| 1 | Нажатие "Подтвердить" на карточке Level 3 | Открытие модалки отправки лицензии |
| 2 | Ввод данных лицензии | Текстовое поле |
| 3 | Отправка | `submitLicenseVerification(uid, license)`. Пересчёт уровня. |

### 8.6 Пересчёт уровня верификации (`calcVerificationLevel`)

```
if (licenses.length > 0 || certificates.length > 0)  → Level 3
else if (inn || passportScan)                         → Level 2
else if (phoneVerified && emailVerified)              → Level 1
else                                                  → Level 0
```

## 13. Диаграммы переходов состояний

### 13.1 Состояния заявки (Request)

```
    ┌──────────┐
    │   OPEN   │ ← Создание заявки
    └────┬─────┘
         │  "Взять в работу" (supplier)
         ▼
    ┌──────────┐
    │ ASSIGNED │
    └────┬─────┘
         │  "Начать обработку"
         ▼
  ┌──────────────┐
  │ IN_PROGRESS  │
  └──┬───────┬───┘
     │       │
     ▼       ▼
┌─────────┐ ┌──────────┐
│COMPLETED│ │ REJECTED │
└─────────┘ └──────────┘
```

### 13.2 Уровни верификации

```
Level 0 (Регистрация)
    │  +email verified +phone verified
    ▼
Level 1 (Базовая)
    │  +ИНН / паспорт
    ▼
Level 2 (Паспортные данные) → Разблокирует: чаты, заявки
    │  +лицензии / сертификаты
    ▼
Level 3 (Полная верификация) → Бейдж "Проверенный"
```

### 13.3 Экраны аутентификации

```
[Не аутентифицирован]
    │  Нажатие "Войти"
    ▼
[AuthModal: Email + Пароль]
    │
    │ Нажатие "Войти"
    ▼
[signInWithPassword]
    │              │
    │ Успех        │ Ошибка (нет аккаунта)
    ▼              ▼
[Главная]    [signUp + auto-login]
                   │
                   ▼
              [Главная]
```

### 13.4 Подписки поставщика

```
FREE (0 KGS) → BASIC (990 KGS) → PRO (2990 KGS) → ENTERPRISE (9990 KGS)
  5 товаров      20 товаров        100 товаров       ∞ товаров
  0 бюджет       5 KGS/день        15 KGS/день       20 KGS/день
```
