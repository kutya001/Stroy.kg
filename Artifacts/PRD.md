## 1. Видение продукта

### 1.1 Миссия

**Stroy.kg** — единая платформа для строительного рынка Кыргызстана, которая соединяет покупателей строительных товаров и услуг с поставщиками и подрядчиками, упрощая процесс поиска, сравнения и заказа.

### 1.2 Видение

Стать крупнейшим цифровым маркетплейсом строительных материалов и услуг в Центральной Азии, начиная с Кыргызской Республики.

### 1.3 Проблема

Строительный рынок Кыргызстана характеризуется:

- **Фрагментированностью** — поставщики разрознены, нет единого каталога
- **Непрозрачностью цен** — покупатели не могут быстро сравнить предложения
- **Сложностью поиска** — нет удобного инструмента для поиска конкретных строительных материалов по характеристикам
- **Отсутствием доверия** — нет системы верификации поставщиков
- **Неэффективностью коммуникации** — заказчики вынуждены обзванивать десятки поставщиков

### 1.4 Решение

Веб-платформа (mobile-first) с:
- Структурированным каталогом строительных товаров и услуг (21 группа, 8 этапов строительства)
- Системой заявок — покупатель публикует потребность, поставщики откликаются
- Встроенным мессенджером
- Многоуровневой верификацией для построения доверия
- Системой продвижения для поставщиков (монетизация)

## 6. Ключевые функциональные модули

### 6.1 Аутентификация и регистрация

**Бизнес-ценность:** Барьер входа минимален (регистрация по телефону), при этом верификация обеспечивает доверие и безопасность.

| Функция | Описание | Бизнес-обоснование |
|---------|----------|-------------------|
| Регистрация по SMS | Вход/регистрация по номеру +996 через OTP | Низкий барьер входа, привычный для КР |
| Выбор роли | Consumer / Supplier / Developer | Персонализация опыта с первого входа |
| Согласие с офертой | Обязательный чекбокс | Юридическая защита платформы |
| Админ-вход | Пароль вместо SMS | Повышенная безопасность административного доступа |

### 6.2 Каталог товаров и услуг

**Бизнес-ценность:** Ядро платформы. Структурированный каталог решает проблему фрагментированности рынка.

| Функция | Описание | Бизнес-обоснование |
|---------|----------|-------------------|
| Иерархическая категоризация | Категория → Вид → Группа → Наименование (21 группа) | Точный подбор по строительной специфике |
| Характеристики | Динамические поля (Марка бетона, Длина и т.д.) | Технические требования покупателей |
| 8 этапов строительства | Проектирование → Благоустройство | Поиск товаров под конкретный этап работ |
| Режимы отображения | Сетка / Таблица / Поставщики | Удобство для разных задач |
| Расширенные фильтры | Цена, рейтинг, продвижение, новинки | Быстрый поиск нужного товара |
| Бейджи ТОП / НОВИНКА / РЕКОМЕНДОВАНО | Визуальные метки на карточках | Привлечение внимания к продвигаемым товарам |

### 6.3 Система заявок

**Бизнес-ценность:** Инвертированная модель продаж — покупатель описывает потребность, поставщики конкурируют за заказ.

| Функция | Описание | Бизнес-обоснование |
|---------|----------|-------------------|
| Создание заявки | Подробное описание потребности с уточнениями | Поставщик получает точный запрос, меньше отказов |
| Уточняющий блок | Вид → Группа → Характеристики | Снижение числа "непопаданий" |
| Pre-fill с товара | Заявка из карточки товара | Сокращение пути покупателя до заказа |
| Статусная модель | OPEN → ASSIGNED → IN_PROGRESS → COMPLETED/REJECTED | Прозрачность процесса для обеих сторон |
| Уведомления | Поставщикам при новой заявке, покупателю при смене статуса | Скорость реакции, не теряются заявки |

### 6.4 Профиль и верификация

**Бизнес-ценность:** Доверие — фундамент B2B маркетплейса. Верификация защищает от мошенничества.

| Функция | Описание | Бизнес-обоснование |
|---------|----------|-------------------|
| 4 уровня верификации | Телефон → Email → ИНН/Паспорт → Лицензии | Градация доверия, мотивация к полной верификации |
| Гейты доступа | Чаты и заявки требуют Level 2 | Защита от спама и некачественных участников |
| Бейдж "Проверенный" (Level 3) | Визуальная метка на карточке поставщика | Преимущество для верифицированных |

### 6.5 Мессенджер

**Бизнес-ценность:** Удержание коммуникации внутри платформы. Данные о переписках = понимание спроса.

## 7. Бизнес-логика

### 7.1 Логика верификации

```
Регистрация (Level 0)
    │
    ├── Подтвердить email + телефон → Level 1
    │       └── Отправить ИНН/паспорт → Level 2 (разблокирует чаты и заявки)
    │               └── Отправить лицензии/сертификаты → Level 3 (бейдж "Проверенный")
    │
    └── Без верификации → только просмотр каталога и ленты
```

**Правило:** Чаты (`canAccessChat`) и заявки (`canAccessRequests`) требуют **Level 2+**. Это защищает поставщиков от спама и мотивирует покупателей верифицироваться.

### 7.2 Логика заявок

1. **Покупатель** создаёт заявку → статус `OPEN`
2. Система отправляет **уведомление** всем подходящим поставщикам
3. **Поставщик** принимает заявку → статус `ASSIGNED` (привязан конкретный поставщик)
4. Поставщик начинает обработку → `IN_PROGRESS`
5. Финал: `COMPLETED` (успех) или `REJECTED` (отказ)
6. При каждой смене статуса — **уведомление покупателю**

**Бизнес-правило:** Одна заявка может быть назначена только одному поставщику (MVP). В будущем — аукционная модель с несколькими откликами.

### 7.3 Логика подписок и лимитов

| Действие | Проверка | При превышении |
|----------|---------|----------------|
| Добавить товар | `count(products) < plan.maxProducts` | Предупреждение о лимите |
| Включить продвижение | `budget <= plan.maxAdBudget` | Слайдер ограничен максимумом |
| Изменить бюджет рекламы | `budget >= 1 && budget <= plan.maxAdBudget` | Ограничение диапазона |

### 7.4 Логика отображения контента по ролям

| Роль | Главная | Каталог | Заявки | Навигация |
|------|---------|---------|--------|-----------|
| Consumer | Товары + рекомендации | Режим покупателя | Создание + "Мои заявки" | Каталог, Создать, Чаты |
| Supplier | Заявки + рек. поставщик | Общий + собственный | Входящие заявки | Мой каталог, Добавить |
| Developer | = Supplier | = Supplier | = Supplier | = Supplier |
| Admin | Зависит от view-as | Полный доступ | Зависит от view-as | Админ-панель |

### 7.5 Логика номенклатуры

Строительный рынок структурирован в **4-уровневую иерархию**:

```
Категория (2)
  └── Вид (7)
        └── Группа (21) ← основной уровень фильтрации
              └── Наименование (товар/услуга) ← конкретный продукт
```

**Пример цепочки:** Товар → Материалы → Бетон → "Бетон М300 B22.5 W8 F200"

Каждая группа имеет свой набор **характеристик** (ключ-значение), специфичных для строительной отрасли:
- Бетон: Марка, Класс прочности, Морозостойкость, Подвижность, Объём
- Арматура: Класс, Диаметр, Длина, Марка стали
- Электрика: Тип, Напряжение, Сечение

## 12. Риски и допущения

### 12.1 Риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| **Низкая adoption** | Средняя | Высокое | Фокус на Бишкек, оффлайн-промо на строительных базарах |
| **Недостаток поставщиков** | Средняя | Высокое | Ручной онбординг первых 50 поставщиков, бесплатный тариф |
| **Качество данных** | Высокая | Среднее | Верификация уровня 2+ для активных участников |
| **Масштабирование Firebase** | Низкая | Среднее | Firestore автомасштабируется, мониторинг затрат |
| **SMS-спам** | Средняя | Среднее | RecaptchaVerifier, лимиты Firebase |
| **Конкуренция от OLX** | Низкая | Среднее | Нишевая экспертиза (строительство), верификация |

### 12.2 Допущения

1. Строительный рынок КР активно переходит в онлайн
2. Покупатели готовы верифицироваться для получения доступа к функциям
3. Поставщики готовы платить за подписку при наличии заявок
4. Мобильный интернет в КР достаточно развит для веб-приложений
5. Русский язык достаточен для MVP (кыргызский — на следующем этапе)
