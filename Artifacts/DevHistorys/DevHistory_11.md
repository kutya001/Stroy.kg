# DevHistory 11

Версия проекта — 1.5.0.0

Дата — 28 марта 2026

---

## Запрос

Реализовать 7 функциональных блоков:
1. CRUD справочников (номенклатурные группы, этапы строительства) для администратора
2. Мобильная навигация для роли `admin`
3. Функционал профиля покупателя: «Мои заказы» → `/create`, модальное окно уведомлений с бейджем
4. Блокировка кнопки чата в карточке товара
5. Аналитика и статистика в админ-панели (группировка по ролям, заявки по статусам, товары поставщиков)
6. Ограничение верификации уровня 3 для покупателей (`consumer`)
7. Добавление 12 тестовых аккаунтов (5 supplier, 5 consumer, 2 developer)

## Анализ

Админ-панель не имела инструментов управления справочниками и аналитики. Мобильная навигация не содержала пункта для админа. Профиль покупателя имел неактивные кнопки «Мои заказы» и «Уведомления». Кнопка чата на странице товара работала, но по ТЗ должна быть заблокирована. Верификация уровня 3 (лицензии) была доступна всем ролям, хотя для `consumer` максимум — уровень 2. Тестовых аккаунтов было недостаточно для проверки всех ролей.

## Фактически внесённые изменения

### 1. CRUD справочников (`lib/mockDb.ts`, `app/admin/page.tsx`)

**Слой данных (`lib/mockDb.ts`):**
- `constructionStages` изменён с `const` на `let` для поддержки мутаций
- Добавлен in-memory store `nomenclatureGroupsStore` с копией `nomenclatureGroups`
- Реализованы CRUD-функции для номенклатурных групп:
  - `getAllNomenclatureGroups()` — чтение всех групп
  - `createNomenclatureGroup(data)` — создание с автогенерацией `id`
  - `updateNomenclatureGroup(id, data)` — обновление по `id`
  - `deleteNomenclatureGroup(id)` — удаление по `id`
- Реализованы CRUD-функции для этапов строительства:
  - `getAllConstructionStages()` — чтение
  - `addConstructionStage(name)` — добавление (с проверкой дубликатов)
  - `removeConstructionStage(name)` — удаление
  - `updateConstructionStage(oldName, newName)` — переименование

**Интерфейс (`app/admin/page.tsx`):**
- Добавлена табовая навигация: _Пользователи_ | _Справочники_ | _Аналитика_
- Компонент `DirectoriesTab`:
  - Таблица номенклатурных групп с колонками: Категория, Вид, Группа, Характеристики, Действия
  - Форма создания/редактирования с полями: `Категория` (select Товар/Услуга), `Вид` (select зависит от категории), `Наименование` (text), `Характеристики` (динамический массив строк с кнопками добавления/удаления)
  - Кнопки редактирования (Pencil) и удаления (Trash2) для каждой строки
  - Секция «Этапы строительства» — список с inline-редактированием, удалением и добавлением новых этапов

### 2. Мобильная навигация для администратора (`components/Navigation.tsx`)

- Добавлена проверка `const isAdmin = userData?.role === 'admin'`
- При `isAdmin === true` отображается отдельный набор навигации: Главная, Каталог, **Админ** (иконка `ShieldAlert`, маршрут `/admin`), Чат, Профиль
- Тернарная логика: `isAdmin ? [...] : isSupplier ? [...] : [...]`

### 3. Функционал профиля покупателя (`app/profile/page.tsx`)

**Мои заказы и отклики:**
- Кнопка обёрнута в `<Link href="/create">` вместо неактивного `<div>`
- Маршрутизирует на страницу списка заявок

**Уведомления:**
- Импортированы `getMockNotifications`, `markNotificationAsRead`, `markAllNotificationsRead` из `mockDb`
- Добавлено состояние `showNotifications` и `notifications`
- Вычисляемый `unreadCount` = количество уведомлений с `read: false`
- На кнопке «Уведомления» отображается красный бейдж с числом непрочитанных (до 9+)
- При клике открывается модальное окно с полным списком уведомлений:
  - Непрочитанные выделены фоном `bg-primary/5` и жирным шрифтом
  - Индикатор-точка слева для непрочитанных
  - Кнопка «Прочитать все» в заголовке модалки
  - Клик по уведомлению помечает его прочитанным
  - Пустое состояние с иконкой Bell

### 4. Блокировка чата в карточке товара (`app/product/[id]/page.tsx`)

- Кнопка «Написать продавцу» заменена:
  - Убран `onClick={handleChatClick}`
  - Установлен `disabled` атрибут
  - Стили: `opacity-50 cursor-not-allowed`, цвет рамки и текста изменён на `border-slate-200 text-slate-400`

### 5. Аналитика и статистика (`app/admin/page.tsx`)

Компонент `AnalyticsTab`:
- **Сводные карточки**: общее число пользователей, покупателей (синий), поставщиков (оранжевый), застройщиков (фиолетовый)
- **Статистика покупателей**: таблица с колонками — Покупатель, Всего заявок, и по каждому статусу (OPEN, ASSIGNED, IN_PROGRESS, COMPLETED, REJECTED). Данные из `getAllMockRequests()` фильтруются по `authorId === uid`
- **Статистика поставщиков**: таблица — Поставщик, Товаров (из `getProductsBySupplierId`), Всего заявок, и по статусам. Фильтрация по `assignedSupplierId === uid`
- **Статистика застройщиков**: таблица — Застройщик, Товаров, Заявок, Верификация

### 6. Ограничение верификации уровня 3 (`app/profile/page.tsx`)

- В секции прогресс-бара верификации для карточки «Ур. 3 — Лицензии»:
  - При `userData?.role === 'consumer'` вместо кнопки «Заполнить» отображается текст «Недоступно для покупателей» (`text-xs text-slate-400`)
  - Для `supplier` и `developer` кнопка остаётся функциональной
- `calcVerificationLevel` в `mockDb.ts` уже корректно ограничивает уровень 3 только для `supplier`/`developer`
- `ProfileEditor.tsx` уже условно рендерит секции сертификатов/лицензий только для `supplier`/`developer`
