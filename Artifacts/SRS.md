## 1. Введение

### 1.1 Назначение документа

Настоящий документ описывает полные требования к программному обеспечению платформы **Stroy.kg** — маркетплейса строительных товаров и услуг в Кыргызской Республике. Документ предназначен для разработчиков, тестировщиков, архитекторов и бизнес-стейкхолдеров.

### 1.2 Область применения

Stroy.kg — это веб-платформа (PWA-ready), которая связывает заказчиков (покупателей) строительных товаров/услуг с поставщиками, подрядчиками и застройщиками на рынке Кыргызстана. Система охватывает:

- Регистрацию и аутентификацию пользователей по номеру телефона
- Каталог товаров и услуг с иерархической категоризацией
- Систему заявок (запросов) от покупателей к поставщикам
- Мессенджер (чаты) между участниками
- Управление профилем и многоуровневую верификацию
- Подписки и продвижение для поставщиков
- Панель администратора

## 2. Общее описание системы

### 2.1 Контекст продукта

Stroy.kg — это B2B/B2C маркетплейс, ориентированный на строительный рынок Кыргызстана. Платформа решает проблему фрагментированности рынка строительных материалов и услуг, предоставляя единую точку для поиска, сравнения и заказа.

### 2.2 Пользовательские роли

Система поддерживает **4 роли** пользователей:

| Роль | Код | Описание |
|------|-----|----------|
| **Заказчик (Consumer)** | `consumer` | Покупатель строительных товаров и услуг. Создаёт заявки, просматривает каталог, общается с поставщиками. |
| **Поставщик (Supplier)** | `supplier` | Продавец товаров/услуг. Публикует товары в каталог, обрабатывает заявки, управляет подпиской и продвижением. |
| **Застройщик (Developer)** | `developer` | Строительная организация. Сочетает функции покупателя и поставщика. Имеет доступ к добавлению товаров. |
| **Администратор (Admin)** | `admin` | Полный доступ ко всем функциям. Модерация пользователей и верификации. Переключение ролей для тестирования. |

### 2.3 Среда функционирования

- **Клиент:** Современные браузеры (Chrome, Safari, Firefox, Edge). Mobile-first дизайн.
- **Серверная часть:** Next.js 15 (App Router), серверные компоненты + клиентские компоненты.
- **База данных:** Firebase Cloud Firestore.
- **Аутентификация:** Firebase Auth (Phone, Email).
- **Хостинг:** Vercel (рекомендуется) / любой Node.js хост.

### 2.4 Ограничения дизайна

- Mobile-first подход (min-width: 375px)
- Брендинг: Primary (#E87722), Secondary (#1E3A5F), Accent (#F5C842)
- Шрифты: Unbounded (заголовки), Golos Text (основной текст)
- Иконки: библиотека lucide-react
- Кыргызский сом (KGS) как валюта по умолчанию

## 4. Функциональные требования

### 4.1 Модуль аутентификации (FR-AUTH)

#### FR-AUTH-01: Регистрация и вход по телефону
- **Приоритет:** Высокий
- **Описание:** Пользователь вводит номер телефона в формате +996XXXXXXXXX. Firebase Auth отправляет 6-значный SMS-код (OTP).
- **Входные данные:** Номер телефона (+996), чекбокс согласия с офертой
- **Процесс:**
  1. Пользователь вводит номер телефона
  2. Отмечает чекбокс "Согласие с офертой" (обязателен)
  3. Нажимает "Отправить код"
  4. Firebase отправляет SMS с 6-значным OTP
  5. Пользователь вводит полученный код
  6. При верном коде — аутентификация
  7. Если пользователь новый — выбор роли (Consumer/Supplier/Developer)
- **Выходные данные:** Аутентифицированная сессия (Firebase JWT)
- **Ограничения:** Таймер обратного отсчёта 300 секунд для повторной отправки OTP

#### FR-AUTH-02: Вход по Email
- **Приоритет:** Средний
- **Описание:** Альтернативный способ входа для пользователей с подтверждённым email.
- **Процесс:** Ввод email → OTP на почту → Верификация кода
- **Ограничения:** Только для существующих пользователей

#### FR-AUTH-03: Вход администратора
- **Приоритет:** Высокий
- **Описание:** При вводе специального номера (+996555000000) система запрашивает пароль вместо OTP.
- **Процесс:** Ввод спецномера → Ввод пароля → Верификация → Вход в панель администратора

#### FR-AUTH-04: Управление сессией
- **Приоритет:** Высокий
- **Описание:** Сессии управляются Firebase Auth (JWT refresh). Данные пользователя сохраняются в localStorage.
- **Требования:**
  - Автоматическое восстановление сессии при перезагрузке
  - Кнопка выхода с полной очисткой состояния
  - Loading-индикатор при проверке сессии

#### FR-AUTH-05: Выбор роли при регистрации
- **Приоритет:** Высокий
- **Описание:** Новый пользователь обязан выбрать роль: Заказчик, Поставщик или Застройщик.
- **Ограничения:** Роль нельзя изменить после выбора (только через админ-панель).

#### FR-AUTH-06: Смена номера телефона
- **Приоритет:** Средний
- **Описание:** Пользователь может изменить привязанный номер через `PhoneAuthProvider.credential` + `updatePhoneNumber`.
- **Процесс:** Профиль → "Изменить номер" → Ввод нового номера → OTP → Подтверждение

### 4.2 Модуль каталога (FR-CAT)

#### FR-CAT-01: Просмотр каталога товаров
- **Приоритет:** Высокий
- **Описание:** Все пользователи могут просматривать каталог опубликованных товаров и услуг.
- **Режимы отображения:**
  - **Сетка (Grid):** Карточки 3 в ряд с изображением, ценой, рейтингом
  - **Таблица (Table):** Конфигурируемые колонки с сортировкой
- **Информация на карточке:** Изображение, бейджи (ТОП/НОВИНКА/рекомендация), рейтинг, поставщик, регион, группа, этап строительства, название, описание, характеристики, цена, теги

#### FR-CAT-02: Фильтрация и поиск
- **Приоритет:** Высокий
- **Описание:** Многоуровневая система фильтрации:
  - **Текстовый поиск** — по названию, поставщику, описанию, тегам
  - **Категория** — Товар / Услуга (кнопки-переключатели)
  - **Вид** — динамический список на основе категории
  - **Группа** — динамический список на основе вида
  - **Этап строительства** — 8 этапов (Проектирование, Геодезия, Фундамент, Каркас и стены, Кровля, Инженерные сети, Отделка, Благоустройство)
  - **Расширенные фильтры:**
    - Диапазон цен (min-max)
    - Минимальный рейтинг (4+, 4.5+, 4.8+)
    - Только продвигаемые товары
    - Только новые товары
- **Индикатор:** Счётчик активных фильтров, кнопка "Сбросить все"

#### FR-CAT-03: Режим просмотра поставщиков
- **Приоритет:** Средний
- **Описание:** Переключение каталога в режим отображения поставщиков (для покупателей).
- **Фильтр:** Все / Только товары / Только услуги / Смешанные
- **Карточка поставщика:** Аватар, бейдж верификации, тип, количество позиций, рейтинг, подписка, ссылка на каталог поставщика

#### FR-CAT-04: Каталог поставщика (собственный)
- **Приоритет:** Средний
- **Описание:** Поставщик видит только свои товары в каталоге с возможностью управления.
- **Функции:** Просмотр своих товаров, быстрое добавление нового товара

#### FR-CAT-05: Рекомендованный поставщик
- **Приоритет:** Низкий
- **Описание:** Баннер рекомендованного поставщика в нижней части каталога. Отображает статистику: товары, рейтинг, верификация, подписка.

### 4.3 Модуль заявок (FR-REQ)

#### FR-REQ-01: Создание заявки (покупатель)
- **Приоритет:** Высокий
- **Описание:** Покупатель создаёт заявку на товар/услугу с детальной спецификацией.
- **Требование доступа:** Верификация уровня ≥ 2 (ИНН/Паспорт)
- **Поля формы:**
  - Категория (Товар/Услуга) — обязательно
  - Название заявки — обязательно
  - Количество + единица измерения
  - Срок выполнения (дата)
  - Бюджет (KGS)
  - Описание (текстовое поле)
  - Фото/документы (drag & drop)
  - **Уточнения (расширяемая секция):**
    - Вид (динамические кнопки)
    - Группа (динамические кнопки)
    - Характеристики (динамические поля на основе группы)
- **Pre-fill:** При переходе с карточки товара (`?productId=X`) поля предзаполняются

#### FR-REQ-02: Список заявок покупателя
- **Приоритет:** Высокий
- **Описание:** Покупатель видит все свои заявки с текущим статусом.
- **Информация:** Категория, статус, название, описание, объём, бюджет, количество откликов, назначенный поставщик
- **Действия:** Отмена заявки (если не завершена/отклонена)

#### FR-REQ-03: Обработка заявок (поставщик)
- **Приоритет:** Высокий
- **Описание:** Поставщик видит входящие заявки и может их обрабатывать.
- **Статусная модель:**

```
OPEN → ASSIGNED → IN_PROGRESS → COMPLETED
                              → REJECTED
```

- **Действия по статусам:**
  - `OPEN` → "Взять в работу" → `ASSIGNED`
  - `ASSIGNED` → "Начать обработку" → `IN_PROGRESS`
  - `IN_PROGRESS` → "Завершить" → `COMPLETED`
  - `IN_PROGRESS` → "Отклонить" → `REJECTED`

#### FR-REQ-04: Детальная страница заявки
- **Приоритет:** Средний
- **Описание:** Полная информация о заявке для поставщика с действиями в зависимости от статуса.
- **Маршрут:** `/request/[id]`

#### FR-REQ-05: Уведомления по заявкам
- **Приоритет:** Средний
- **Описание:** При создании заявки — уведомление поставщикам. При смене статуса — уведомление автору заявки.

### 4.4 Модуль профиля и верификации (FR-PROF)

#### FR-PROF-01: Просмотр и редактирование профиля
- **Приоритет:** Высокий
- **Описание:** Пользователь просматривает и редактирует свои данные.
- **Отображаемые данные:** Аватар (инициалы), имя, email, компания, ИНН, роль, уровень верификации, подписка
- **Редактирование:** Имя, email, компания, телефон (через OTP-флоу)

#### FR-PROF-02: Многоуровневая верификация
- **Приоритет:** Высокий
- **Описание:** 4-уровневая система верификации с прогресс-баром:

| Уровень | Название | Требования | Разблокирует |
|---------|----------|------------|-------------|
| **0** | Не верифицирован | Регистрация по телефону | Просмотр каталога, ленты |
| **1** | Базовая | Подтверждение email + телефона | — |
| **2** | Паспортные данные | ИНН / паспорт | Чаты, заявки, полный функционал |
| **3** | Полная верификация | Лицензии, сертификаты | Бейдж "Проверенный", приоритет в выдаче |

- **Процесс верификации:**
  - Уровень 1: Ввод email → Отправка OTP на email → Ввод кода
  - Уровень 2: Ввод ИНН (10+ цифр) → Автоматическая проверка (mock: всегда успех)
  - Уровень 3: Отправка лицензии/сертификата → Ручная проверка администратором

#### FR-PROF-03: Подписки (для поставщиков)
- **Приоритет:** Средний
- **Описание:** 4 тарифных плана с разными лимитами:

| План | Цена | Макс. товаров | Бюджет продвижения |
|------|------|---------------|-------------------|
| **FREE** | 0 KGS/мес | 5 | 0 KGS/день |
| **BASIC** | 990 KGS/мес | 20 | 5 KGS/день |
| **PRO** | 2 990 KGS/мес | 100 | 15 KGS/день |
| **ENTERPRISE** | 9 990 KGS/мес | ∞ | 20 KGS/день |

#### FR-PROF-04: Смена пароля
- **Приоритет:** Низкий
- **Описание:** Смена пароля через модальное окно (текущий пароль → новый пароль → подтверждение).
- **Ограничения:** Минимум 6 символов.

#### FR-PROF-05: Страница поставщика
- **Приоритет:** Средний
- **Описание:** Публичная страница поставщика (`/supplier/[id]`) с товарами/услугами в виде сетки.
- **Данные:** Аватар, имя, компания, верификация, рейтинг, количество товаров

### 4.5 Модуль чатов (FR-CHAT)

#### FR-CHAT-01: Список диалогов
- **Приоритет:** Высокий
- **Описание:** Пользователь видит все активные чаты, отсортированные по дате последнего сообщения.
- **Требование доступа:** Верификация уровня ≥ 2
- **Элементы:** Аватар собеседника, имя, бейдж верификации, последнее сообщение, время, счётчик непрочитанных
- **Поиск:** По имени контакта

#### FR-CHAT-02: Диалог (переписка)
- **Приоритет:** Высокий
- **Описание:** Обмен текстовыми сообщениями в реальном времени.
- **Функции:**
  - Отправка текстового сообщения (Enter или кнопка)
  - Отображение времени отправки (HH:MM)
  - Визуальное разделение отправленных/полученных сообщений
  - Автопрокрутка к последнему сообщению
  - Уведомление собеседнику при новом сообщении

### 4.6 Модуль товаров (FR-PROD)

#### FR-PROD-01: Добавление товара
- **Приоритет:** Высокий
- **Описание:** Поставщик/Застройщик/Админ добавляет товар в каталог.
- **Пошаговая форма:**
  1. Выбор категории (Товар/Услуга)
  2. Выбор вида (динамический)
  3. Выбор группы (динамический)
  4. Заполнение характеристик (динамические поля по группе)
  5. Основные данные: название, цена, единица, этап строительства
  6. Описание
  7. Загрузка фото (до 4 шт.)
  8. Опции публикации:
     - Тоггл "Опубликовать на доске"
     - Тоггл "Продвижение" + слайдер бюджета (1—20 сом/день)
- **Ограничения:** Количество товаров ограничено подпиской

#### FR-PROD-02: Иерархия номенклатуры
- **Приоритет:** Высокий
- **Описание:** 4-уровневая система классификации:

- **Категории:** Товар, Услуга
- **Виды:**
  - Товар → Инструменты, Материалы, Оборудование
  - Услуга → Архитектурные, Строительные, Отделочные, Аренда
- **Группы (21 шт.):** Бетон, Кирпич, Арматура, Пиломатериалы, Цемент, Утеплители, Кровельные, Электрика, Сантехника, Краски, Ручной инструмент, Электроинструмент, Измерительные, Генераторы, Бетоносмесители, Леса/Подмости, Проектирование, Монтажные работы, Штукатурно-малярные, Аренда техники, Земляные работы
- **Характеристики:** Динамические поля, зависящие от группы (напр., Бетон: Марка, Класс прочности, Морозостойкость, Подвижность, Объём)

#### FR-PROD-03: Продвижение товара
- **Приоритет:** Средний
- **Описание:** Поставщик может активировать продвижение с дневным бюджетом.
- **Диапазон:** 1—20 KGS/день (зависит от подписки)
- **Эффект:** Бейдж "РЕКОМЕНДОВАНО" в каталоге, приоритет в выдаче

### 4.7 Модуль ленты / главная (FR-FEED)

#### FR-FEED-01: Главная страница (покупатель)
- **Приоритет:** Высокий
- **Описание:** Персонализированная лента с приветствием, навигационными кнопками, новостями, рекомендациями и каталогом товаров.
- **Секции:**
  1. Приветствие + локация + статус верификации
  2. Строка поиска
  3. Навигационные кнопки (Каталог, Создать заявку, Поставщики, Чаты)
  4. Новости (3 карточки с тегами)
  5. Рекомендации (4 топ-товара)
  6. Баннер "Создать заявку"
  7. Фильтры (Все/Товары/Услуги)
  8. Сетка товаров

#### FR-FEED-02: Главная страница (поставщик)
- **Приоритет:** Высокий
- **Описание:** Лента входящих заявок с боковой панелью рекомендованного поставщика.
- **Секции:**
  1. Приветствие (с названием компании)
  2. Навигационные кнопки (Мой каталог, Добавить товар)
  3. Новости
  4. Фильтры заявок
  5. Список заявок (8 колонок)
  6. Боковая панель — рекомендованный поставщик (4 колонки, sticky)

### 4.8 Модуль администрирования (FR-ADMIN)

#### FR-ADMIN-01: Панель администратора
- **Приоритет:** Высокий
- **Описание:** Управление платформой с ограничением доступа (только роль `admin`).
- **Функции:**
  - Статистика: общее количество пользователей, верифицированные, поставщики, ожидают верификации
  - Переключатель ролей для тестирования (просмотр от лица Consumer/Supplier/Developer)
  - Список пользователей, ожидающих верификации, с кнопками повышения уровня
  - Таблица всех пользователей (имя, роль, телефон, верификация, подписка)

#### FR-ADMIN-02: Переключение ролей
- **Приоритет:** Средний
- **Описание:** Администратор может переключить вид интерфейса для тестирования.
- **Индикация:** Оранжевый баннер в шапке при активном режиме просмотра от другой роли.

### 4.9 Модуль уведомлений (FR-NOTIF)

#### FR-NOTIF-01: Система уведомлений
- **Приоритет:** Средний
- **Описание:** Внутренние уведомления о событиях платформы.
- **Типы:**
  - `request` — Новая заявка
  - `response` — Отклик на заявку
  - `system` — Системные уведомления (смена статуса заявки)
  - `verification` — Уведомления о верификации
  - `chat` — Новое сообщение в чате
- **Действия:** Пометить как прочитанное, пометить все как прочитанные
- **Индикация:** Счётчик непрочитанных в шапке (колокольчик)

## 6. Варианты использования (Use Cases)

### UC-01: Регистрация нового пользователя

| Поле | Значение |
|------|---------|
| **Актёр** | Новый пользователь |
| **Предусловие** | Пользователь не аутентифицирован |
| **Основной сценарий** | 1. Открывает приложение → 2. Нажимает "Войти" → 3. Вводит номер +996... → 4. Ставит галочку оферты → 5. Нажимает "Отправить код" → 6. Получает SMS с 6-значным OTP → 7. Вводит код → 8. Выбирает роль (Заказчик/Поставщик/Застройщик) → 9. Перенаправляется на главную |
| **Альтернативный** | 7а. Неверный код — сообщение об ошибке, повторный ввод |
| **Постусловие** | Пользователь аутентифицирован, роль назначена, сессия создана |

### UC-02: Покупатель ищет товар в каталоге

| Поле | Значение |
|------|---------|
| **Актёр** | Заказчик (Consumer) |
| **Предусловие** | Пользователь аутентифицирован |
| **Основной сценарий** | 1. Переходит в "Каталог" → 2. Выбирает категорию "Товар" → 3. Фильтрует по виду "Материалы" → 4. Фильтрует по группе "Бетон" → 5. Устанавливает ценовой диапазон → 6. Просматривает результаты в режиме сетки/таблицы → 7. Нажимает на карточку товара |
| **Альтернативный** | 6а. Нет результатов — отображается "Товары не найдены" |
| **Постусловие** | Пользователь видит отфильтрованный список товаров |

### UC-03: Покупатель создаёт заявку

| Поле | Значение |
|------|---------|
| **Актёр** | Заказчик (Consumer), верификация ≥ 2 |
| **Предусловие** | Пользователь аутентифицирован и верифицирован (Level 2+) |
| **Основной сценарий** | 1. Переходит в "Создать заявку" → 2. Выбирает категорию → 3. Заполняет название, количество, бюджет → 4. Раскрывает секцию уточнений → 5. Выбирает вид и группу → 6. Заполняет характеристики → 7. Нажимает "Опубликовать" → 8. Заявка появляется в списке со статусом OPEN |
| **Альтернативный** | 1а. Пользователь переходит с карточки товара — поля предзаполнены |
| **Постусловие** | Заявка создана, уведомление отправлено поставщикам |

### UC-04: Поставщик обрабатывает заявку

| Поле | Значение |
|------|---------|
| **Актёр** | Поставщик (Supplier) |
| **Предусловие** | Есть открытая заявка (OPEN) |
| **Основной сценарий** | 1. Видит заявку в ленте/списке → 2. Нажимает "Подробнее" → 3. Изучает детали заявки → 4. Нажимает "Взять в работу" (ASSIGNED) → 5. Нажимает "Начать обработку" (IN_PROGRESS) → 6. Нажимает "Завершить" (COMPLETED) |
| **Альтернативный** | 6а. Нажимает "Отклонить" → статус REJECTED |
| **Постусловие** | Заявка завершена, уведомление покупателю |

### UC-05: Поставщик добавляет товар

| Поле | Значение |
|------|---------|
| **Актёр** | Поставщик (Supplier) / Застройщик (Developer) |
| **Предусловие** | Пользователь имеет роль supplier/developer/admin |
| **Основной сценарий** | 1. Переходит в "Добавить товар" → 2. Выбирает категорию → 3. Выбирает вид → 4. Выбирает группу → 5. Заполняет характеристики → 6. Вводит название, цену, единицу → 7. Загружает фото → 8. Включает публикацию/продвижение → 9. Нажимает "Добавить в каталог" |
| **Ограничения** | Количество товаров ≤ лимита подписки |
| **Постусловие** | Товар добавлен в каталог, виден покупателям (если опубликован) |

### UC-06: Пользователь проходит верификацию

| Поле | Значение |
|------|---------|
| **Актёр** | Любой зарегистрированный пользователь |
| **Предусловие** | Верификация < Level 3 |
| **Основной сценарий** | 1. Переходит в "Профиль" → 2. Видит прогресс верификации → 3. Нажимает "Подтвердить" на следующем уровне → 4. Заполняет требуемые данные (email/ИНН/лицензия) → 5. Подтверждает (OTP/ввод данных) → 6. Уровень повышается |
| **Постусловие** | Уровень верификации повышен, новые функции разблокированы |

### UC-07: Переписка в чате

| Поле | Значение |
|------|---------|
| **Актёр** | Заказчик + Поставщик, оба верификация ≥ 2 |
| **Предусловие** | Оба участника верифицированы (Level 2+) |
| **Основной сценарий** | 1. Покупатель нажимает "Чат" на карточке товара → 2. Открывается диалог → 3. Вводит сообщение → 4. Нажимает "Отправить" → 5. Поставщик получает уведомление → 6. Поставщик открывает чат → 7. Отвечает |
| **Постусловие** | Сообщения доставлены обоим участникам |

### UC-08: Администратор управляет верификацией

| Поле | Значение |
|------|---------|
| **Актёр** | Администратор (Admin) |
| **Предусловие** | Вход как admin |
| **Основной сценарий** | 1. Переходит в "Панель администратора" → 2. Видит статистику → 3. Просматривает список пользователей, ожидающих верификации → 4. Проверяет данные (ИНН, лицензии) → 5. Нажимает кнопку повышения уровня |
| **Постусловие** | Уровень верификации пользователя повышен |

| `notifications` | Уведомления |

### 8.3 REST API (планируемый)

В MVP используется прямое взаимодействие с Firestore через SDK. В будущем планируется REST API через Next.js API Routes.

### 8.4 Интерфейс пользователя (UI)

- **Навигация:** Нижняя панель навигации (mobile) с ролезависимыми пунктами + верхняя шапка с логотипом, поиском, уведомлениями
- **Модальные окна:** AuthModal, OnboardingModal, ChangePasswordModal, ChangePhoneModal, ResetPasswordModal, ProfileEditor
- **Адаптивность:** Grid-система (1-3 колонки в зависимости от ширины экрана)

## 9. Ограничения и допущения

### 9.1 Ограничения

1. **MVP-версия** — используется in-memory mock-база данных (mockDb.ts); переход на реальный Firestore запланирован
2. **SMS-аутентификация** — ограничена бесплатным тарифом Firebase (10 SMS/мин по умолчанию)
3. **Платежи** — не реализованы в MVP; подписки назначаются вручную
4. **Файлы** — загрузка фото/документов не реализована (mock UI)
5. **Реальное время** — чат работает через polling, а не через WebSocket/Firestore listeners
6. **Единственный язык** — русский (i18n не поддерживается в MVP)
7. **Единственная валюта** — KGS (кыргызский сом)

### 9.2 Допущения

1. Все пользователи имеют доступ к интернету и современному браузеру
2. Номера телефонов начинаются с +996 (Кыргызстан)
3. Поставщики честно указывают данные при верификации (валидация ИНН — mock)
4. Один пользователь = один аккаунт = один номер телефона

## 10. Глоссарий

| Термин | Определение |
|--------|------------|
| **Заказчик** | Пользователь, который покупает товары/услуги (consumer) |
| **Поставщик** | Пользователь, который продаёт товары/услуги (supplier) |
| **Застройщик** | Строительная организация, сочетающая функции покупателя и продавца (developer) |
| **Заявка** | Запрос покупателя на приобретение товара/услуги |
| **Номенклатура** | Иерархическая классификация товаров и услуг |
| **Верификация** | Процесс подтверждения личности и данных пользователя |
| **Продвижение** | Платная опция для приоритетного показа товаров в каталоге |
| **Подписка** | Тарифный план для поставщиков с лимитами |
| **Этап строительства** | Фаза строительного процесса для фильтрации товаров |
| **Онбординг** | Начальная настройка профиля после регистрации |
